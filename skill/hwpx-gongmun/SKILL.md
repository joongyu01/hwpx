# 한글 공문(hwpx) 작성

## 이 스킬이 동작하는 원리

hwpx는 XML 파일 여러 개를 묶은 zip이다. 글꼴·문단 모양은 `Contents/header.xml`에 번호로 정의되고, 본문 `Contents/section0.xml`은 그 번호를 참조한다. XML을 처음부터 새로 지으면 번호가 어긋나 파일이 깨지거나 서식이 사라진다. 다른 도구가 hwpx를 제대로 못 만드는 이유가 대부분 이것이다.

그래서 이 스킬은 XML을 짓지 않는다. 실제 결재 문서에서 뽑아낸 **서식 원형** `templates/default.hwpx`에서 문단과 표를 복제하고 글자만 바꾼다. 생성은 `scripts/build.js`가 전부 맡는다. 네가 할 일은 **내용을 좋은 공문 문장으로 써서 JSON에 담는 것**이다. XML을 직접 고치고 싶어지면 멈추고 JSON으로 해결할 방법을 찾아라.

## 작업 순서

1. **자료 파악.** 사용자가 준 자료(저장소 README, 메모, 기존 문서)를 읽고 문서 유형을 정한다. 사용자의 역할과 상대 부서를 대화에서 파악한다. 작성 부서, 협조 부서, 일정처럼 지어낼 수 없는 정보만 짧게 묻는다. 물어볼 상황이 아니면 합리적으로 가정하고 마지막에 가정했다고 알린다.
2. **내용 JSON 작성.** 형식은 `references/spec.md`를 읽고 따른다. 작업 폴더나 임시 폴더에 `내용.json`으로 저장한다.
3. **생성.**
   ```bash
   node <스킬경로>/scripts/build.js 내용.json --out-dir <저장폴더>
   ```
   오류가 나면 메시지가 몇 장 몇 번째 항목인지 알려준다. JSON을 고쳐 다시 실행한다. 파일명은 `(부서)제목_YYMMDDHHmm.hwpx`로 자동으로 붙는다.
4. **확인.** Windows에 한글이 설치돼 있으면 실제로 열어 쪽 이미지를 보고 확인한다. 표가 넘치거나 줄바꿈이 어색하면 JSON 문장을 다듬어 다시 만든다.
   ```bash
   powershell -NoProfile -ExecutionPolicy Bypass -File <스킬경로>/scripts/hwp-preview.ps1 -Hwpx 결과.hwpx -OutDir 미리보기
   ```
   한글이 없는 환경이면 이 단계는 건너뛰고, 사용자에게 한글에서 열어 확인해 달라고 한다.
5. **전달.** 파일 위치, 문서 구성, 네가 가정한 부분(일정·역할 분담·결재선·수치)을 알린다.

Node.js가 없는 환경이면 사용자에게 `web/index.html` 생성기 페이지를 안내한다. 네가 만든 JSON을 그 페이지에 붙여넣으면 같은 파일이 만들어진다.

## 공문 문장 쓰는 법

결재권자가 30초 안에 핵심을 파악하게 쓰는 것이 목표다. 그래서 문장보다 개조식, 설명보다 결론이 앞선다.

- **명사형으로 끝낸다.** "~함", "~임", "~필요", "~예정", "~곤란", "~확보", "~가능". "~합니다", "~했다"는 쓰지 않는다.
- **□ 항목은 `(라벨) 본문` 구조다.** 라벨은 2~7자 명사구로 그 항목의 요지를 말한다. 예: (추진근거), (현황), (문제점), (추진체계), (소요예산), (기대효과). 본문은 1~2줄, 대략 90자 이내로 쓴다.
- **길어지면 쪼갠다.** 한 □에 내용이 셋 이상 들어가면 `ㅇ` 하위 항목으로 나눈다. 출처, 기준일, 용어 풀이 같은 보충은 `*` 각주로 내린다.
- **제목과 부제.** 제목은 "~ 계획(안)", "~ 결과 보고", "~ 개선 방안", "~ 협조 요청"으로 끝난다. 부제는 목적을 담아 "~을 위한"으로 끝낸다. 「」는 생성기가 붙인다.
- **요약 한 문장.** 표지 다음 ▸ 상자에 들어간다. "무엇을 왜 하고자 함"을 한 문장으로 쓴다.
- **숫자는 자료에 있는 것만 쓴다.** 결재 문서의 수치는 그대로 인용되고 책임이 따른다. 자료에 없으면 "○○개소", "△△백만원"처럼 비워두고 사용자에게 채워달라고 말한다.
- **표는 비교·역할 분담·일정에 쓴다.** 셀에는 2~3줄까지만 넣는다. 셀에 목록을 넣으면 글머리표가 붙는다.

## 문서 유형 고르기

장(章) 구성은 기관이 달라도 거의 같다. 국가공무원인재개발원 「정책기획 실습」의 보고서 유형·기본구조와 부처 계획서 목차를 바탕으로 12개 유형을 `scripts/doctypes.js`에 정리해 두었다. 장 구성을 새로 지어내지 말고 여기서 고른다. 결재권자가 익숙한 순서라야 빨리 읽힌다.

```bash
node <스킬경로>/scripts/doctypes.js            # 유형 목록
node <스킬경로>/scripts/doctypes.js result     # 결과 보고의 장 구성과 작성 요령
```

| 묶음 | 유형(id) |
|---|---|
| 계획 | 추진 계획(안) `plan` · 시스템 구축 계획(안) `system` · 종합계획·중장기 전략 `master` · 연간 사업계획 `annual` · 행사·회의 개최 계획 `event-plan` |
| 결과·상황 | 결과 보고 `result` · 행사·회의 결과 보고 `event-result` · 상황·동향 보고 `status` |
| 검토·개선 | 검토 보고 `review` · 개선 방안 `improve` · 진단·분석 보고 `diagnosis` |
| 협조 | 협조 요청 `request` |

- 사용자가 유형을 말하지 않으면 요청과 자료를 보고 가장 가까운 유형을 고른다. 고른 유형을 마지막에 알린다.
- 장 제목과 순서는 그대로 쓴다. "선택" 장은 자료가 있을 때만 넣는다. 유형의 `extras`는 필요할 때 장으로 추가한다.
- 각 장의 `guide`는 무엇을 쓸지 알려주는 안내다. 문서에 옮겨 적지 않는다.
- 사용자가 빈 틀만 원하면 `node scripts/doctypes.js <id> --skeleton 틀.json`으로 틀을 만들고 `build.js`로 hwpx를 만든다. 작성 요령이 * 각주로 들어간 양식이 나온다.

## 결재선과 표지

- `team`은 작성 부서다. 결재표와 머리띠에 들어간다.
- `approval`은 결재 칸 세 개(담당, 부서장, 최종 결재자)의 직위와 이름이다. 이름은 사용자가 알려준 경우에만 넣는다. 결재 문서에 남의 이름을 지어 넣으면 안 된다.
- `disclosure`는 공개구분이다. 기본값은 "비공개"다.
- `date`는 표지 날짜로 "2026. 9." 형식이다. 없으면 이번 달이 들어간다.

## 다른 서식을 쓰고 싶을 때

사용자가 자기 부서 양식 hwpx를 주면서 "이 양식으로" 라고 하면 `references/template-guide.md`를 읽고 그 파일을 생성기용 서식으로 만든다. 만든 서식은 `--template` 옵션으로 쓴다. 한 번 만든 서식은 사용자에게 저장해 두라고 알려준다.

## 문제 해결

- **"hwpx 파일로 읽을 수 없습니다"**: 사내 DRM이 걸렸거나 구버전 hwp다. 한글에서 열어 "다른 이름으로 저장 → hwpx"로 저장한 파일을 받는다.
- **한글에서 파일이 안 열림**: `node scripts/inspect.js 결과.hwpx`로 문단 구조를 확인한다. 서식을 새로 만든 경우라면 자리표시자 `{{...}}`가 한 덩어리로 남아 있는지 본다.
- **특수문자**: `&`, `<`, `>`는 생성기가 알아서 처리한다. JSON에서는 따옴표만 조심한다.
