# 내용 JSON 형식

생성기(`scripts/build.js`, 웹 페이지)가 받는 입력이다. 전체 예시는 `examples/good-station.json`에 있다.

## 목차

1. 최상위 필드
2. 장(sections)과 항목(items)
3. 항목 종류별 쓰는 법
4. 줄글 약식 표기
5. 표(table)
6. 붙임(attachments)
7. 서식 전용 자리표시자(fields)
8. 굵게 강조(**)
9. 요약 쪽(brief)
10. 첨부 쪽(appendices)
11. 생성 전 점검 경고

## 1. 최상위 필드

| 필드 | 필수 | 들어가는 곳 | 예 |
|---|---|---|---|
| `title` | 예 | 표지 제목, 머리띠 제목, 파일명 | `"착한주유소 가격 현황판 구축 계획(안)"` |
| `team` | 권장 | 결재표 등록번호 칸, 머리띠 부서명, 파일명 | `"AI전환팀"` |
| `subtitle` | 권장 | 머리띠 부제. 「」는 자동 | `"데이터 기반 가격관리를 위한"` |
| `coverSubtitle` | 선택 | 표지 부제. 없으면 `subtitle` 사용 | `"가격기준 상시점검을 위한"` |
| `summary` | 권장 | ▸ 요약 상자 한 문장 | `"~을 자체 구축·운영하고자 함"` |
| `date` | 선택 | 표지 날짜. 없으면 이번 달 | `"2026. 9."` |
| `year` | 선택 | 등록일자·결재일자 칸 연도. 없으면 `date`에서 추출 | `"2026"` |
| `approval` | 선택 | 결재 칸 3개 `{position, name}` | 아래 참고 |
| `disclosure` | 선택 | 공개구분. 기본 "비공개" | `"공개"` |
| `cooperator` | 선택 | 협조자 칸 | `"사업관리팀장"` |
| `sections` | 예 | 본문 장 목록 | 2절 |
| `attachments` | 선택 | 붙임 목록. 마지막에 "끝." 자동 | 6절 |
| `brief` | 선택 | 표지 다음 요약 쪽 | 9절 |
| `appendices` | 선택 | 본문 뒤 첨부 쪽 | 10절 |
| `fields` | 선택 | 사용자 서식의 추가 자리표시자 | 7절 |

`approval` 예시다. 순서대로 담당, 부서장, 최종 결재자 칸에 들어간다. 이름을 모르면 빈 문자열로 둔다.

```json
"approval": [
  { "position": "담당", "name": "" },
  { "position": "AI전환팀장", "name": "" },
  { "position": "사업이사", "name": "" }
]
```

`approval`을 아예 빼면 "담당", "`team`장", 빈칸이 들어간다.

## 2. 장(sections)과 항목(items)

```json
"sections": [
  {
    "title": "추진배경",
    "items": [ 항목, 항목, ... ]
  }
]
```

- 장 번호 Ⅰ, Ⅱ, Ⅲ은 순서대로 자동으로 붙는다. `title`에 번호를 쓰지 않는다.
- 장 제목 다음, □ 항목 사이, 장 끝에는 빈 줄이 자동으로 들어간다.

## 3. 항목 종류별 쓰는 법

| `type` | 모양 | 필드 |
|---|---|---|
| `box` | ` □ (라벨) 본문` | `label`(선택), `text`, `subs`(선택), `notes`(선택) |
| `sub` | `ㅇ 본문` 하위 항목 | `text` |
| `note` | `  * 본문` 각주 | `text` |
| `text` | 기호 없는 줄글 | `text` |
| `table` | 표 | 5절 |

`box`에 `subs`와 `notes`를 붙이면 그 □ 바로 아래에 ㅇ 항목과 * 각주가 순서대로 들어간다.

```json
{
  "type": "box",
  "label": "자료수집",
  "text": "오피넷 판매가격을 매일 2회 자동 수집하여 판정 결과를 갱신",
  "subs": ["수집·판정·배포 전 과정을 자동화"],
  "notes": ["원본은 압축 보관하여 판정식 변경 시 재산정 가능"]
}
```

`label`이 없으면 괄호 없이 ` □ 본문`으로 들어간다.

## 4. 줄글 약식 표기

항목을 객체 대신 문자열로 써도 된다. 다른 AI에게 JSON을 받을 때 실수가 가장 적은 방식이다.

| 문자열 | 해석 |
|---|---|
| `"(라벨) 본문"` | box, 라벨 있음 |
| `"□ (라벨) 본문"` | 위와 같음 |
| `"본문"` | box, 라벨 없음 |
| `"ㅇ 본문"` | sub |
| `"* 본문"` | note |

```json
"items": [
  "(현황) 착한주유소 472개소 운영 중",
  "ㅇ 서울·경기 비중이 전체의 35%",
  "* 2026. 9. 5. 기준"
]
```

라벨 안에 괄호가 또 있으면 라벨로 인식하지 못한다. 그럴 때는 객체로 쓴다.

## 5. 표(table)

```json
{
  "type": "table",
  "columns": ["구분", "AI전환팀(구축)", "사업관리팀(운영)"],
  "rows": [
    ["내용", ["설계·개발 및 배포", "기술지원"], ["점검 총괄", "명단 관리"]],
    ["기한", "10월", "상시"]
  ],
  "widths": [1, 2.4, 2.4],
  "keyColumn": true
}
```

| 필드 | 설명 |
|---|---|
| `columns` | 머리행. 음영과 굵은 글씨가 들어간다. 빼면 머리행 없이 만든다 |
| `rows` | 행 목록. 각 행은 칸 배열이다 |
| 칸이 문자열 | 한 문단. `\n`으로 줄을 나눌 수 있다 |
| 칸이 배열 | 항목마다 한 줄씩, 글머리표가 붙는다 |
| `widths` | 열 너비 비율. 빼면 첫 열을 좁게 나머지를 고르게 나눈다 |
| `keyColumn` | 기본 `true`. 첫 열을 가운데 정렬 굵은 글씨로 만든다. 첫 열도 일반 칸이면 `false` |

표 전체 너비는 본문 폭에 맞춰진다. 칸이 너무 많으면 글자가 좁아지므로 4열 이하를 권장한다.

## 6. 붙임(attachments)

```json
"attachments": ["화면 구성(안)", "판정기준 요약 1부."]
```

- 하나면 `붙임  화면 구성(안)  1부.  끝.`으로 들어간다.
- 둘 이상이면 번호가 붙고 마지막 줄 끝에 "끝."이 붙는다.
- "1부."가 없으면 자동으로 붙인다.

붙임이 없으면 "끝."도 넣지 않는다. 계획(안)·보고서 형식에서는 보통 생략한다.

## 7. 서식 전용 자리표시자(fields)

사용자가 만든 서식에 기본 목록에 없는 자리표시자가 있으면 `fields`로 채운다.

```json
"fields": { "DOC_NO": "AI전환팀-2026-031", "RECEIVER": "사업관리팀장" }
```

기본 자리표시자는 다음과 같다. 최상위 필드가 자동으로 채우지만 `fields`로 덮어쓸 수 있다.

`TEAM` `TITLE` `COVER_SUBTITLE` `HEADER_SUBTITLE` `SUMMARY` `DATE` `YEAR` `DISCLOSURE` `COOP` `POS1` `POS2` `POS3` `NAME1` `NAME2` `NAME3`

채울 값이 없는 자리표시자는 빈칸이 된다.

## 8. 굵게 강조(**)

`**`로 감싼 구절이 굵게 들어간다. 결재권자가 꼭 봐야 할 결론 구절 하나만 감싼다.

```json
"(문제점) 수기 점검으로는 전국 472개소를 **주 1회 이상 확인하기 곤란**"
```

- 굵게 바뀌는 곳: □ 본문, ㅇ 하위 항목, 요약 쪽 ○ 항목, 요약 비교 상자.
- 제목·표·각주·첨부 머리띠에서는 별표만 지워진다.
- `**` 개수가 홀수면 굵게 처리하지 않고 별표만 지우며, 점검 경고를 띄운다.

## 9. 요약 쪽(brief)

표지 다음 쪽에 한 쪽짜리 요약을 넣는다. 요약 쪽에는 쪽 번호가 찍히지 않고, 본문은 새 쪽에서 시작한다.

```json
"brief": {
  "title": "착한주유소 가격 현황판 구축 계획(안)(요약)",
  "subtitle": "데이터 기반 가격관리를 위한",
  "compare": ["(기존) 수기 점검 **월 1회**", "(개선) 자동 수집 **하루 2회**"],
  "sections": [
    { "title": "추진 배경 및 목적", "items": ["(배경) 요약 문장 **결론**", "* 각주"] },
    { "title": "향후 계획", "items": ["(일정) 10월 시범 운영, 11월 확대"] }
  ]
}
```

| 필드 | 설명 |
|---|---|
| `title` | 선택. 빼면 문서 제목 뒤에 "(요약)"이 붙는다 |
| `subtitle` | 선택. 빼면 문서 `subtitle` |
| `compare` | 선택. 제목 아래 비교 상자 줄 목록. `"(라벨) 본문"` 또는 `{label, text}` |
| `sections` | 대분류 목록. `title`은 □ 머리, `items`는 ○ 항목(`"(라벨) 본문"`)과 `"* 각주"` |

요약 쪽에는 표를 넣지 않는다. 대분류 3~5개, 대분류마다 ○ 2~4개가 한 쪽 분량이다.

## 10. 첨부 쪽(appendices)

본문 뒤에 새 쪽으로 시작하는 첨부를 넣는다. 머리띠는 첨부가 하나면 "첨부", 둘 이상이면 "첨부 1", "첨부 2"다.

```json
"appendices": [
  { "title": "교육생 주요 의견", "items": ["(본부·연구소) 요약 의견", "* 익명 처리함"] },
  { "title": "세부 일정표", "items": [{ "type": "table", "columns": ["회차", "일자", "대상", "인원"], "rows": [["1", "9. 1.(화)", "○○본부", "○○명"]] }] }
]
```

`items`는 본문 장의 `items`와 같은 형식이다(2~5절). 한 첨부가 한 쪽을 넘지 않게 쓴다.

`attachments`(붙임 목록 한 줄)와 함께 써도 된다. 붙임 목록은 본문 끝, 첨부 쪽은 그 뒤에 들어간다.

## 11. 생성 전 점검 경고

생성기는 파일을 만들면서 다음을 경고로 알린다. 경고가 있어도 파일은 만들어지지만, 결재 전에 고친다.

| 경고 | 뜻 |
|---|---|
| 날짜 검산 | `2026. 9. 16.(수)` 처럼 요일을 붙인 날짜가 달력과 다름 |
| 띄어쓰기 두 칸 | 문장 안에 연속 공백 |
| 채우지 않은 칸 | `○○`, `△△` 가 남아 있음 |
| 강조 짝 | `**` 개수가 홀수 |

만든 파일이 한글에서 열릴 구조인지는 `node scripts/verify.js 결과.hwpx`로 확인한다.
